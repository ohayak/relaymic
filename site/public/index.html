Microphone passthrough for remote Macs

Speak into a Mac
that isn't in the room.

Remote desktop forwards your screen, your keyboard and your mouse. It doesn't forward your voice. Remote Visio does — as a real system microphone on the Mac you're controlling, so dictation, Zoom and everything else simply find it in the input list.

Why you couldn't find this already

Every remote tool forwards a screen. None of them carry a voice to a Mac.

Windows has had microphone redirection since RDP shipped it — one line in a config file. The moment the machine on the other end is a Mac, the feature is gone from every tool on the market. Not hidden in a menu. Not there.

TeamViewer's own community threads confirm a remote session captures audio from the remote machine's microphone, not from yours; the feature request for transmitting your local mic is still open. Remote Visio doesn't replace your remote desktop tool — it runs beside whichever one you already use.

Setup, in order

Install once on the Mac. After that it's one address in a browser.

01

Install on the Mac you remote into

Hand the repository and its SETUP.md to your AI assistant, or follow it yourself: put both machines on Tailscale, run make install-driver from Terminal (it builds the bundled Remote Visio audio driver with clang from the Xcode Command Line Tools, installs it to /Library/Audio/Plug-Ins/HAL with one admin password and restarts coreaudiod — system audio pauses for about a second), build the receiver and start it. It prints the address to open. Runs on macOS 14.2 or later.

02

Open the receiver's address wherever you are

A Windows laptop, an iPad, a borrowed machine in an office — any browser that has a microphone. Open the https://<mac>:7420 address the receiver printed (over Tailscale, or any network where that port is reachable), accept the self-signed certificate once, press Start talking. The connection is direct between the two devices.

03

Choose Remote Visio as the input

In Zoom, in dictation, in Audacity, in whatever is running over there. To the Mac it is an ordinary microphone, so nothing needs to know Remote Visio exists.

Where the work actually went

Sending audio is easy. The last 200 milliseconds are not.

Remote Visio started as a tool its author needed daily, across three Macs, and every parameter below is there because something broke without it.

A jitter buffer sized for real networks

150 ms of target depth, measured rather than guessed. The 20 ms that sounds brilliant on a LAN turns into stuttering the first time you use hotel Wi-Fi.

Silence suppression deliberately off

DTX saves bandwidth by not sending silence. It also clips the front of a quietly spoken word, and dictation loses the first syllable. Speech doesn't need the savings.

Three recording taps for when it sounds wrong

Before processing, after the buffer, and read back out of the virtual device. "It sounded bad" becomes a waveform you can point at, on the segment where it happened.

Questions worth asking first

What it does, and what it deliberately doesn't.

Does it matter which remote desktop software I use?

No. Remote Visio doesn't hook into TeamViewer, AnyDesk, Parsec, RustDesk, Jump Desktop or anything else — it carries audio on its own connection and presents a microphone on the Mac. Your remote tool keeps doing screen and input, unaware anything changed. You can also use Remote Visio with no remote desktop tool at all.

Do I need to install anything on the device I'm speaking from?

No. The sending side is a web page. Chrome, Edge, Safari or Firefox on Windows, macOS, Linux, iPad or Android — whatever is in front of you, including machines you're not allowed to install software on.

What happens to my audio on the way?

It goes browser to Mac over an encrypted peer-to-peer connection — in most cases directly, without passing through us at all. When two networks refuse to connect directly, the stream falls back to a relay that forwards encrypted packets and stores none of them. We never hold recordings, and there is no server-side transcription.

What is the virtual audio device it installs?

Remote Visio's own Core Audio HAL plug-in, bundled with the project and built from driver/RemoteVisio.c by make install-driver. It appears as an input device named "Remote Visio" everywhere (Zoom: Settings → Audio → Microphone → Remote Visio; dictation: System Settings → Sound → Input → Remote Visio), and it deliberately cannot be chosen as the Mac's sound output, so installing it never hijacks the Mac's speakers. make uninstall-driver removes it cleanly. Check it is present with system_profiler SPAudioDataType | grep Remote Visio; if it isn't, make install-driver has already printed codesign and coreaudiod diagnostics — read those, retry sudo killall coreaudiod, or reboot. If you still have BlackHole from an older version you may remove it with brew uninstall --cask blackhole-2ch — Remote Visio ignores it either way.

I'm on Windows connecting to Windows. Do I need this?

No — Microsoft RDP already redirects your microphone, at no cost. Remote Visio exists because that feature has no equivalent when the far end is a Mac. Use what's free where it works.

My iPhone and my Mac are in the same room. Do I need this?

Probably not. Apple's Continuity already lets a nearby iPhone act as a Mac microphone for free. Remote Visio is for distance: different building, different city, different country.

How much delay is there really?

Roughly a phone call. On a direct connection you're looking at a network round trip plus a 150 ms buffer that absorbs the jitter real networks produce. It's built for talking, dictating and meetings — not for monitoring yourself while recording music.

What does it cost?

Nothing. It's AGPL-3.0 open source. There is no paid tier, no account, and no server of ours in the path — which also means there is nothing for us to bill you for. If you need a TURN relay for networks that refuse to connect directly, you bring your own.

How rough is it, honestly?

It's the author's own tool, opened up. A menu-bar app and an installer package that you build from source (signed and notarized with your own Developer ID), UI in seven languages, English logs and docs, and you need Tailscale (or an equivalent) so the sending browser can reach the Mac. The audio path itself is the mature part — three Macs use it daily, and the buffer and gain parameters are what they are because something broke without them.

Give the Mac over there a microphone.

Clone it, hand the repo to your AI assistant, and tell it to follow SETUP.md. It installs the dependencies, builds, and then teaches you how to use it.
